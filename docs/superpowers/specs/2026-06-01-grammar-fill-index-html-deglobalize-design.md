# 设计：grammar-fill/index.html "顺势收尾"——让骨架退化成装配清单

> 日期：2026-06-01
> 方案：A（纯原生，不引入构建工具）
> 状态：待用户复核

## 背景与动机

`docs/grammar-fill/index.html` 已达 **9731 行 / 392KB**，体感"越来越大、要撑不住"。

体检结论：**架构没有病危，是重心失衡。** 之前的"高聚合低耦合"重构是真实有效的——`grammar-fill/modules/` 下已抽出 22 个模块，`shared/` 下 9 个公共模块。问题在于 `index.html` 仍然**既是骨架又是引擎**：

| 内容 | 行数 | 性质 |
|------|------|------|
| 内联 CSS `<style>` | ~3571 行 | 纯样式，与逻辑无关 |
| HTML 骨架 + 42 个 `<script>` 引入 | ~420 行 | 页面结构 + 装配清单 |
| 内联 JS 主控引擎（行 3999–9731） | ~5732 行 | "遗留核心"，新功能持续堆积于此 |

触发点是"隐隐不安"，**无具体故障**。因此这是预防性养护，不是抢修——刻意排除推倒重来与重型框架。

## 目标（终态）

```
grammar-fill/
├── index.html      ← 只剩三样：HTML骨架 + <script>装配清单 + ~10行启动代码
├── styles.css      ← 【新】原 <style> 内 ~3571 行
└── modules/        ← 现有 22 个 + 从引擎搬出的新模块
```

**"做完了"的硬标准**：`index.html` 里搜不到一个业务函数定义。
一旦达成，新功能物理上无处堆进 `index.html`，文件大小自然封顶——"不安"被结构性消除。

## 非目标（严守边界）

- ❌ 不引入构建工具（Vite/webpack）；GitHub Pages 无构建部署照旧
- ❌ 不改用框架（React/Vue）
- ❌ 不动 `shared/`、不动其他题型
- ❌ 不发明新的模块通信机制——沿用现有 `window.Grammar*` 全局命名约定
- ❌ 不顺手做无关重构

将来若真要"多题型 + 大量共享代码"，再评估升级方案 B（Vite + ES 模块）。本方案刻意把 A 做干净，使将来升 B 是平滑一步而非重写。

## 执行顺序（按"收益÷风险"，每步独立 commit + 独立验证）

| 步 | 动作 | 影响 | 风险 | 验证 |
|----|------|------|------|------|
| **0** | 立规矩：写下铁律"index.html 不再进业务逻辑"；定 module 文件头三件套（职责/用法/依赖） | 防止白干 | 无 | — |
| **1** | 抽 CSS → `styles.css`，`<style>` 换 `<link>` | 9731→~6160 行（省 37%） | 极低 | 页面截图对比一致 |

| **3** | 搬投影模式（~190 行，最孤立）练手，跑通流程 | 引擎 ↓ | 低 | 投影功能照旧 |

| **5** | 搬侧边栏 + 迁移训练数据源（~880/750 行） | 引擎 ↓ | 中 | 切换/迁移照旧 |

**可中断性**：步骤 3–6 每块结束时，`index.html` 都更瘦且功能完整，架构不会处于半残状态。做到第 4 步想停就停。

## 模块抽取的统一手法（每块搬迁遵循）

1. 在 `modules/` 新建文件，文件头写三件套注释（职责/用法/依赖）。
2. 用 IIFE 包裹，按现有约定把入口挂到 `window.GrammarXxx`（参照 `app-state.js`、`teaching-render.js`）。
3. 显式依赖通过函数参数或 `deps` 对象传入（参照现有 `focusRuleDeps()` / `teachingViewModelDeps()` 模式），不在模块内直接抓散落全局。
4. 在 `index.html` 的 `<script>` 装配清单中按正确加载顺序加入引用。
5. 删除 `index.html` 内对应内联代码，替换为对模块入口的调用。
6. 单独 commit，单独验证。

## 验证策略

- **每步**：加载页面，确认被搬功能行为不变（肉眼 + 截图对比）。
- 复用现有 `playwright.config.js` + `tests/` 既有测试。
- 走既定发布流程：feature 分支 → main → push → GitHub Pages（seeklume.work）。
- CSS 抽离后特别确认：暗色主题、投影模式、响应式布局无回归。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 加载顺序错乱导致 `window.X` 未定义 | 装配清单严格保序；每步只动一块，出错即定位 |
| CSS 抽离后路径/选择器失效 | 整体平移不改内容；截图逐屏对比 |
| 半抽离的 app-state 胶水（~27–1100）最缠绕 | 放到最后处理，或留在 index.html 作为"启动代码"的一部分，不强求清空 |

## 护栏（防止重新长大）

1. index.html 封顶：终态只剩骨架 + 装配清单 + 启动码。
2. 新功能一律进 module，不进 index.html。
3. 每个 module 文件头注明：职责 / 用法 / 依赖。
4. 沿用 `window.Grammar*` 命名约定，不引入新机制。
