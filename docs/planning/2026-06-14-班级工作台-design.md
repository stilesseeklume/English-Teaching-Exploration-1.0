# 班级工作台 · 设计（2026-06-14）

> 起因：用户反馈「考点画像 与 学生管理 两页数据不同步、且功能重复」。  
> 经 brainstorming 确认方向：**合成一个「班级工作台」**，内部用**分段切换**呈现两个视角。  
> 本文为该 slice 的设计基准，实现计划另见 writing-plans 产物。

## 1. 问题（已用源码核实）

两页本质是**同一份云端 `exam_results` 的两种切法**，却各自挂了班级管理：

- **数据不同步（真 bug）**：班级人数口径不一致。
  - 考点画像（`renderBoardPage`）：人数 = 该班**云端有成绩的学生数**（只数 `exam_results` 的 `student_no`）。
  - 学生管理（`renderTimelinePage`）：人数 = **云端成绩 ∪ 本地名单**（额外并入 `c.students`）。
  - 后果：只有名单没成绩的班（如「演示班级」40 人）→ 考点画像显示 0、学生管理显示 40。
- **功能重复**：两页都各自有「班级 chips + ＋新建班级」；读的是同一份云端成绩。

## 2. 目标

一页「班级工作台」承载两个视角，结构上根除上述两点：
- 顶部**统一选班 + 统一班级管理**，人数**只算一次**。
- 两视角共用同一次云端拉取与同一份班级列表。
- 班级管理入口收敛到一处（不再两页各一套）。

## 3. 页面结构（一页、一个 dock 入口）

```
班级工作台  (dock 👥)
├─ ① 顶部统一区（两视角共用）
│   ├─ 班级 chips（＋新建班级）           ← 选班；切班两视角同步
│   └─ 选中班管理行：✎改名 · 导入名单 · ＋添加学生 · 🗑删除该班
├─ ② 分段切换： [ 考点视角 | 学生视角 ]      ← 默认「考点视角」
└─ ③ 内容区（按 tab 显示其一）
    ├─ 考点视角：选套卷 chips → 该卷考点画像（排行 + 行内迷你趋势）→ 跨卷趋势(折叠)
    └─ 学生视角：搜索框 → 命中列表（行尾「删」）→ 选中 → 单生可视化画像
```

## 4. 数据流 & 同步修复（核心）

- 进页 / 切班：**一次** `fetchExamResults()`，得到 `allRows`；两视角共用。
- **班级列表只构建一次**，口径统一为 **名单 ∪ 成绩**：cloud rows 的 `class_id/class_name` ∪ 本地 `getClasses()`（含 `c.students`）。两视角拿同一个 `classList` 与 `selectedClassId`。
- 人数 = `Object.keys(stu).length`，其中 `stu` 同时并入 cloud `student_no` 和本地 `c.students`。→ 两视角天然一致。
- 班级管理（改名/导名单/加/删）只在顶部一处；操作后整页重渲染，两视角都反映。

## 5. 导航与兼容

- **dock 两个入口（`考点画像`、`学生管理`）收成一个「班级工作台」**；移除「考点画像」dock 项。
- 路由兼容：`switchPage('error-profile')` → 重定向到工作台并激活**考点视角**；原考点页里「查看单个学生画像 →」按钮 → 改为**切到学生视角**（同页切 tab，更顺）。
- **导入成绩页（`error-import`）保持独立**（数据入口，不在本次合并范围）；其「去学生管理」提示文案改指「班级工作台」。
- 宿主页：**复用 `student-timeline` 页容器**作工作台宿主（它已带名单管理 deps + 最近的 dock/app-state 接线），页标题改「班级工作台」；`error-profile` dock 入口移除、其路由重定向到宿主。`app-state.js` 的 `normalizeDockKey`/`getDockKeyForPage` 把 `error-profile` 收敛到工作台 key（`student-timeline`）。

## 6. tab 状态

- 模块内记住当前激活的 tab（考点/学生），切班保持 tab 不变。
- 默认「考点视角」（讲评是产品核心：先看这个班该重点讲什么）。

## 7. 复用与边界

- 两视角的**内容渲染不重写**：考点视角 = 现 `renderBoardPage` 主体（去掉它自带的班级 chips/新建）；学生视角 = 现 `renderTimelinePage` 主体（去掉它自带的班级 chips/新建/管理行）。班级选择与管理上提到顶部统一区。
- 现有纯函数（`error-profile-render` / `error-profile-view` / `student-tracking` / `error-profile-store`）尽量原样复用，新增仅限「分段切换」相关的视图模型/渲染（如 `workbenchTabsHtml`）。

## 8. 测试

- 单测：班级列表口径一致（名单 ∪ 成绩，演示班级=40 在两视角相同）；tab 状态切换。
- Smoke（合并/更新现有「考点画像」「学生管理」「班级管理」用例）：
  - 进工作台默认「考点视角」出该卷画像；切「学生视角」能搜、能删。
  - 同一班在两视角人数一致（构造一个只有名单、无成绩的班验证 0→40 修复）。
  - 老入口 `switchPage('error-profile')` 解析到工作台。

## 9. 不做（YAGNI）

- 导入成绩页重构、转班/合并班、导出名单。
- 改云端 `exam_results` 表结构 / 任何 Supabase 迁移。
- 改动隐私红线（姓名仍只本机、云端只存学号）。
