# 错题精准训练 · v1 设计（错题 → 画像引擎 → 真题迁移 + 精准讲评）

> 状态：v0.1（2026-06-08）。把现有「杂而无重点」的工具，重做成**以学生错题为中心的精准训练闭环**的 v1 设计。
> 上游：[CLAUDE.md](../../CLAUDE.md) · [PROJECT_CHARTER.md](../../PROJECT_CHARTER.md) · [地基策略 2026-06-07](2026-06-07-foundation-strategy.md)
> 决策人：项目负责人（一线英语教师）。本文经审阅后转 writing-plans。

## 1. 背景与问题

- 现工具「**功能杂、入口杂、没重点**」：Dock 六个入口（套卷 / 考点 / 知识库 / 错题本 / 备课 / AI）平铺并列、权重一样。
- **用 app 在课堂逐题讲评不现实**——讲一套卷从头到尾，中途开网站点两三道题反而耽误进度，老师宁可口述。所以「讲评」不是核心。
- 老师真正看中的：**① 学生错题 ② 从错题拉同考点真题做迁移训练**。备课不重要。

## 2. 重点（v1 的魂）

**学生错题 → 考点画像（引擎）→ 同考点真题迁移训练 + 精准讲评 → AI 教学建议。**

- **画像是引擎，不是主角**：它只回答「该练 / 该讲哪个考点」。
- **差异化不在画像**——智学网 / 好分数 / 七天网络等已把「个人画像 / 学情分析」做得更全、全自动、全校规模，**不在这上面跟它们拼**。
- **差异化在**：「从**老师自己的真题库**、按**老师自己的精细考点（102 tag）**，做**迁移训练 + 讲评闭环**」——真题 + 自有考点体系 + 讲法，不是又一张学情报告。**站在网阅 / 智学网数据的下游，做它们不做的那一段。**

## 3. v1 范围

- **纯老师端**：不做学生登录。学生端（学生进 app 做题 / 班级码轻入口）留到 v1 验证后再说。
- **不砍只降级**：现有六入口**全留**，只从首屏挪进「更多 / 工具」。一个不删 = 没人丢东西。
- **化名化优先**：只用学号，不碰真名。

## 4. 核心循环

| 步骤 | 做什么 | 用什么 |
|---|---|---|
| ① 导入这次考试 | 网阅「学生小题分」导入 | **新** |
| ② 匹配出画像 | 题号 → 题库考点 → 每生 / 班级错误分布 | **新**（已验证）|
| ③ 从弱项开练 | 某考点弱 / **某道具体错题** → 拉全库同考点**真题** → 投屏 / 导出 | 迁移训练（**已有**，入口改成「从弱项 / 从某错题进」）|
| ④ 精准讲评 + 建议 | 重点讲哪几题 + AI 给「讲 X 练 Y」 | **新 framing** + AI |

## 5. 数据与匹配（已用真实数据验证 ✅）

- **输入**：网阅导出的「学生小题分」（.xls）。实测格式：语法填空 = **题号 36–45，每题一列"得分"，1.5 = 对 / 0.0 = 错**；含学号、姓名、班级、各客观题（题号 1–35 带得分+作答）。
- **匹配**：题号 36–45 → 题库里该套卷（如 `2026广州一模`）每题的考点（粗 `category` + 细 `fine_category`）。三套广州一模语法填空都在题号 36–45，对齐。
- **产出（两级）**：① **考点级** —— 每生「错了哪些考点」+ 班级「哪个考点最多人错」；② **题级** —— 因按题号匹配，能定位到**具体哪套卷、哪道题**（含原文 / 答案 / 考点），这些攒起来 = **每个学生的个人错题集**。**迁移可从「一个考点」或「某一道具体错题」两头进。**
- **数据边界（诚实）**：网阅对语法填空只给「对 / 错（得分）」，**没有学生的实际作答**（题号 36–45 无「作答」列）。→ 知道「他第 40 题错了」，但不知道「他写成了什么」。对**迁移（按考点拉题）够用**；**错因分析（写错成啥）这份数据做不了**，需以后让学生补录答案或换数据源。
- **化名化**：导入后只保留 / 展示**学号**（或匿名序号），姓名不入库。
- **验证结果**（2026广州一模 · 17 班 · 48 人，PoC 跑通）：班级介词 77% 错、词性·名词 71%、非谓语·done 58%、词性·形容词 56%、主谓一致 54%…个人画像同步可得（学生 N → 其弱考点）。**机制成立，零手工。**
- **前提**：那套卷得在题库里（题号才查得到考点）。已有 19 套直接用；新卷先走 Word+AI 进库。
- **年份匹配**：靠学号年级推断（2023 级 = 高三 = 2026 届 → 2026广州一模）；导入时让老师确认 / 选择是哪套卷。

**纳入 v1 的「A 组」玩法（几乎免费，因为画像数据已经算出来了）：**
- **🎯 讲评优先级**：画像直接标出「**重点讲（高错）/ 可略过（全对）**」——治「讲卷从头到尾耽误进度」的痛；以后开 app 只为那 2–3 道值得讲的。
- **👥 共性 vs 个性**：高错率考点 = 全班集中讲；个别学生弱点 = 单独派练。**这是教学决策，不是报告。**

## 7. 隐私设计（v1）

- **化名化**：app 内只存 / 显示**学号**；真名留老师**线下花名册**。
- **数据足迹最小**：v1 优先「**客户端导入 + 算画像**」，学生逐题结果尽量**不入云端**（留在老师本机 / 浏览器）。要做趋势（B 组）再谈「受 RLS 保护、按老师隔离的云端存储 + 知情同意」。
- **同意**：一旦涉及个人学生数据的**留存 / 研究使用**，需学生 + 监护人知情同意（未成年人为敏感信息）。

## 8. v1 不做 / 未来玩法（「B 组」，验证后再加）

- 趋势画像（多次考试累积）、个性化练习包（按弱考点自动从真题组卷）、艾宾浩斯复习提醒、AI 生成讲法、跨班 / 跨届对比、家长反馈单、**学生端（B/C）**。
- **原则**：守 YAGNI——先把闭环做到老师真用，再逐个验证加，**别又把首屏堆满**（这正是 v1 要解决的原始病）。不重建智学网。

## 9. 复用 vs 新建

- **复用**：题库 + 考点 tag、Word+AI 解析、迁移训练（从弱项切入）、投影、错题本（演化为班级 / 学生错题）。
- **新建**：网阅导入 + 匹配、考点画像视图（班级 + 个人）、讲评优先级 / 共性个性 framing、画像驱动的 AI 建议、IA 重排。

## 10. 实施切片（粗，每片可单独验证 / 上线）

1. **导入 + 匹配**：读 .xls（语法填空 36–45）→ 匹配题库考点 → 算每生 / 班级错误分布。（PoC 已验证）
2. **班级画像视图**（考点错误排行 + 条形）。

4. **个人画像**（点学生看其弱考点）。

6. **AI 建议**（基于画像）。
7. **IA 重排**：首屏换成训练工作台，六入口收进「更多」。
8. **化名化落实**（只存学号，姓名不入库）。

## 11. 负责人澄清 —— 修正核心模型（2026-06-08，本节为准，覆盖前文相关假设）

实现切片①后负责人澄清，修正前文若干假设：

1. **老题库（baked 19 套）不是匹配中心，只是「迁移训练的弹药库」之一。** §5「前提：那套卷得在题库里」不再是核心路径——别围着老题库转。
2. **核心循环是「每套卷」走一遍**：① 传**这套试题**（Word→AI 解析出考点）② 传**这套成绩**（网阅 .xls）③ 匹配出**完整画像** ④ **数据累积**。每次都是新卷，"传试题"是主路径，呼应「成绩和试题要一起」。
3. **完整画像（无论对错都统计）**：不只统计错题——每考点/每题统计 **对 X / 错 Y / 正确率**，每个学生完整对错 + 错题集。（网阅对语填每题给得分 1.5=对 / 0.0=错 / 空=缺考，足够算完整正确率。）
4. **上传的试题 = 以后的迁移弹药**：每套传入的试题攒进「我的卷子」store，和老题库**合流为迁移题源**。拉同考点真题时从「我的卷子 + 老题库」一起拉。老题库就此退为弹药之一。
5. **数据累积**：历次考试（试题+成绩+画像）一套套攒在**本机（localStorage，v1）**；云端 + RLS + 知情同意为后续。长出每生/班级跨次趋势。
6. **隐私**：学生逐题数据存本机、只显示学号。

**据此修正切片顺序**（覆盖 §10）：
1. **引擎扩展**：完整对错统计（纯模块，扩展切片①的 error-profile.js）—— 先做、最小、是地基。
2. **画像页**：选/传试题 + 传成绩 → 完整画像（2026广州一模在库，可即跑验证）。
3. **试题入「我的卷子」store**：传 Word 新卷 → 入池 → 同时喂画像匹配 + 迁移题源。
4. **累积 + 趋势**：跨历次考试。
5. **从画像弱项拉同考点真题迁移**：pool = 老题库 + 我的卷子。
6. AI 建议、IA 重排提为首屏 等（同前）。

## 12. 精简 IA —— 合并/删除决策（2026-06-09，本节为准，避免系统臃肿）

负责人拍板，全系统精简为「**1 条闭环 + 2 个工具**」：

**核心闭环（首屏主角）**：导入（试题 + 成绩）→ 考点画像 → 去练（迁移）

**合并（砍重复入口、留功能）**：
- **错题本 → 并进画像**（"个人错题集"就是它）；旧错题数据保留为迁移源
- **考点训练 → 画像里的「去练」动作**，不单列
- **备课·导试题 + 导入成绩 → 合成一个「导入」**（试题+成绩一起）；讲题改从「我的卷子 / 题库」进

**降级为工具（不删，挪出首屏主位）**：题库（套卷练习 + 讲题，兼迁移弹药）、知识库（参考）

**删除**：**AI 助手**（烧钱 DeepSeek、范围窄、离核心最远）—— 删 dock 入口 + chat UI/逻辑 + `deepseek-chat` Edge Function

**实施分两片**（各自可验证/上线）：
1. **片 A · 核心**：导入页 + 画像板块 + 本机存储（把现合并页重做成「导入 + 画像板块」两块）
2. **片 B · IA 重排 + 合并 + 删 AI**：首屏三步化、题库/知识库降工具、折叠错题本/考点训练/备课、删 AI

## 13. 班级管理补全（2026-06-14，已上线到 worktree，详见 PROJECT_LOG 同日条目）

「学生管理」页（`renderTimelinePage`）班级管理做全，三动作均搜索/选择器驱动、不平铺：

- **班级改名**：本地改名 + 云端 `class_name` 同步（`cloud.renameExamResultsClass`）。修了 `GrammarErrorProfileStore.renameClass` 抹掉 `students` 名单的隐患（改为 `Object.assign` 保留其它字段）。
- **添加学生**（手动/插班）：折叠框多行粘贴，每行「学号 姓名」或只姓名；纯函数 `parseRosterText` 解析、`addStudentsToClass` 去重保序进名单；缺学号补本地合成键（永不上云）。
- **删除单个学生**：搜索结果行尾「删」→ 本地名单移除（`removeStudentFromClass`）+ 无引用则清本机姓名 + 删云端该班该生成绩（`cloud.deleteExamResultsStudent`）。

数据模型不变：班级 `{id,name,students[学号]}` 本地（owner 隔离）；姓名本地 `grammar-student-names`；云端 `exam_results` 仍只存学号、无姓名。新增 2 个云端函数复用现有 RLS，**无 schema 迁移**。
